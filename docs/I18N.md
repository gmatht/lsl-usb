# I18N plan: lslsetup.exe in every Win95 language

Status: English-only. This doc records the inventory, the size math, and
the work required — so translation can proceed in tiers without redesign.

## 1. String inventory (measured 2026-09-14)

| Source | Count |
|---|---|
| Console messages (`out::info/warn/err/step/prompt`) | ~394 call sites |
| GUI labels/controls (`.text(`) | ~71 call sites |
| UI-ish literals in `src/*.rs` (≥8 chars, contains a space) | ~1,275 literals, **~55 KB English** |

55 KB is the per-language payload (format args fill in at runtime).
European translations expand ~1.0–1.3× vs English.

## 2. Size math

| Coverage | Raw added | Deflated (~2.5:1 on short strings) |
|---|---|---|
| Tier 1: DE FR ES IT NL (+EN built in) | ~0.3 MB | ~0.12 MB |
| Tier 2: all ~24 ANSI retail langs (+RU EL TR) | ~1.3 MB | ~0.5 MB |
| Tier 3: all ~31 boxed langs (+CJK TH HE AR) | ~1.7–2.2 MB | ~0.7–0.9 MB |

Reference: the Win95 exe is ~7.8 MB debug / ~6.0 MB release, of which
~5.3 MB is already vendored bootloader blobs (see §5). Full i18n is
+17–30% raw, under +12% deflated. Offset tables are noise (~5 KB/lang).

## 3. Design: satellite `.lng` files (recommended)

- `lang\de.lng`-style files, one per language, deflate-compressed
  (~25–35 KB each). English stays built in as the fallback.
- At startup: `GetUserDefaultLangID` → load matching `.lng` →
  missing file or missing key falls back to English per string
  (never blank, never crash).
- `flate2` is already linked (we inflate `grldr.gz` at startup), so
  decompression adds zero dependencies: inflate only the active
  language (~60–70 KB resident, milliseconds).
- Alternative (rejected): embedding all languages in the exe preserves
  single-file distribution but forces a rebuild per translator commit
  and bloats every download. UPX whole-exe packing is likewise out —
  its stub plus our custom VC6 `main` entry needs QEMU-proving on real
  Win95; string-level deflate needs no loader tricks.

Key format sketch: `u32 count, u32 offsets[count], nul-terminated
ANSI strings in source-codepage order`, keys = stable numeric IDs
assigned in one `langids` module (never reuse an ID).

## 4. Win95-specific prerequisites (the real work — not bytes)

1. **DBCS audit (`src/sys.rs`).** Byte-level ANSI handling (`c as char`
   casts, manual NUL scans) is not lead-byte safe. Fine for single-byte
   codepages, corrupts CJK paths. Required before Tier 3, unnecessary
   for Tiers 1–2. Decode via `MultiByteToWideChar(CP_ACP)` at the
   boundary, keep UTF-8 inside.
2. **Fixed-pixel layouts.** Dialog rows are fixed width (780px etc.) —
   German runs ~30% longer than English and will clip. Needs dynamic
   sizing or scrollable rows before Tier 1 ships.
3. **Console vs GUI codepages.** GUI renders ANSI (accents fine); the
   Win95 console uses OEM raster fonts, so `é ü ñ` in console output
   may garble. GUI-first languages are safe; console strings need
   OEM-safe wording or explicit conversion.
4. **RTL (Arabic/Hebrew, Tier 3).** Needs `WS_EX_RTLREADING`/mirrored
   dialog layouts; Win95 console BiDi is poor regardless.
5. **CJK fonts are OS-side.** A single ANSI binary renders CJK free on
   a DBCS Win95 once (1) is done — no glyphs ship in the exe.

## 5. Size context (why the exe is ~6 MB — 2026-09-14)

`objdump -h` on the release i586 exe: `.text` (all code incl. std,
nwg, flate2, sha2, VC6 CRT) ≈ **0.5 MB**; `.rdata` (vendored blobs +
strings) ≈ **5.4 MB**. The exe is 90% bootloader payload, not code:

| Blob (embedded raw) | Bytes | Share |
|---|---|---|
| `grubx64.efi` (Canonical-signed GRUB2) | 2,828,168 | ~48% |
| `shimx64.efi` (Microsoft-signed shim) | 968,696 | ~16% |
| `mmx64.efi` (MokManager) | 856,280 | ~14% |
| `BOOTX64.EFI` (grub4dos-for-UEFI) | 417,792 | ~7% |
| `grldr.gz` (stored compressed, inflated at runtime) | 181,527 | ~3% |
| `grldr.mbr`, z0 squashfs, LKDDb cache, strings | ~0.2 MB | ~3% |

The jump to 6 MB came with the vendored signed Secure Boot chain
(~4.6 MB raw, added Sept 11). `strip = true` already saves ~7 MB of
debug sections. Note the exe stores the chain *deflated* since 2026-09-14
(`build.rs` embeds the `.gz`, `nofmt::bundled_signed()` inflates once via
`OnceLock` like `grldr()` — exe 5.95 MB -> 3.81 MB, same runtime
verification); the remaining raw blob is only `BOOTX64.EFI` (418 KB),
whose `.gz` form is a possible ~0.2 MB follow-up.

## 6. Work order

1. Numeric string IDs + English table (no behavior change).
2. `.lng` loader + LangID select + fallback (still English-only).
3. Fixed-pixel layout pass (§4.2).
4. Tier 1 translations (DE FR ES IT NL).
5. Tier 2 (+ remaining ANSI langs).
6. DBCS audit (§4.1), then Tier 3.
7. Optional: deflate the signed chain (§5) — independent saving.
