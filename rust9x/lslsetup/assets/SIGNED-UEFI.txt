Vendored SIGNED UEFI chain for the nofmt (and GPT files-only) install paths:
Microsoft-signed shim -> Canonical-signed GRUB2. Boots with Secure Boot ON,
and (because shim only enforces shim-lock when SB is active) also boots under
SB OFF - so it is strictly more compatible than the unsigned grub4dos-for-UEFI
loader, which is why it is the DEFAULT UEFI loader when these files are
present in the build (override: --uefi-loader grub4dos, or drop any loader in
via --uefi-bootx64 <file>).

Layout written to the stick (all files-only, no formatting):
  \EFI\BOOT\BOOTX64.EFI  = shim (this shimx64.efi)        <-- firmware entry
  \EFI\BOOT\grubx64.efi  = Canonical-signed GRUB2         <-- shim's second stage
  \EFI\BOOT\mmx64.efi    = MokManager (enroll MOKs)       <-- optional, handy
  \EFI\BOOT\grub.cfg     = generated menu (loopback + direct-kernel entries)

shim loads grubx64.efi from its own directory and verifies it against the
embedded Canonical CA; GRUB2 then reads /EFI/BOOT/grub.cfg (its default
config-file fallback). Kernels loaded by that grub must be Canonical-signed
while Secure Boot is ON (Ubuntu/Mint live ISO kernels are; grub's shim_lock
is inactive when SB is OFF, so unsigned kernels still boot then).
