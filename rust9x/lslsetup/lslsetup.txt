Status as of finishing this list (Sep 2026):

[x] Rename the whole subproject to lslsetup / lslsetup.exe
    Done - the subproject (directory, package, exe) is now lslsetup /
    lslsetup.exe (was lsl-install). The embedded manifest was recompiled,
    and run.sh / win95.sh / the PowerShell tests / README were updated.
    (This item was about the subproject, not the TODO file.)

[~] Figure out why text areas are sometimes only a few pixels tall.
    Reported on Windows 10/11 (not Win95). Fix applied but NOT yet
    confirmed on a real Win10/11 box: the two multiline textboxes
    (flatpak-extra IDs on page 2, WSL VHDX on page 3) were built with nwg's
    default flags including ES_AUTOVSCROLL, which on modern Windows can
    auto-size a fixed-height multiline edit to its content and squash it to
    a few pixels. They now use multiline_edit_flags() (no ES_AUTOVSCROLL)
    and re-assert their height after build.
    Guard: tests/win-install-page-test.ps1 asserts each renders >= 60px
    (built at 76px / 160px) on pages 2 and 3. Run it on the Win10/11 box to
    confirm; if page2/page3-multiline-textareas-not-collapsed still goes
    red, the collapse is something else and needs a live repro there.

[x] Figure out why Window sometime just disapears without lauching Rufus.
    Fixed - a rufus::launch failure used to be swallowed (.ok().flatten());
    the window closed and the console looked hung until Rufus (if any)
    appeared. Now the Install working phase turns a launch error into a
    MessageBox + error dialog (fatal_gui) instead of a silent vanish.

[x] If we choose to use the builtin downloader, why don't we get a screen
    asking which USB to use ETC.?
    Already satisfied by the existing design. The INSTALL NOW page (page 5)
    has a "Target USB (for the non-destructive copy)" radio picker of
    removable volumes (harvested into GuiResult.target_usb), and the
    built-in path also prompts on the console via nofmt::choose_target
    ("Choose a stick [1..N]"). No code change was needed.

[x] Slow on deployed machine to fetch hardware, make sure cache is compiled
    into exe
    Fixed. The compiled-in linux-hardware.org snapshot (lsl-hw-cache ->
    build.rs -> EMBEDDED_HW_CACHE, 500 devices) was only a fallback after a
    live fetch. Now hardware::linux_compat_rating consults the embedded
    cache FIRST, so devices in the snapshot rate instantly with no network
    request and never pay the per-device 10s crawl-delay. Only devices not
    in the snapshot fall through to the on-disk cache / one live fetch.
    Unit tests added (hardware::tests::*), 6 pass.

[x] When we choose install why does it download Mint even though we had (1)
    selected to use Zorin on (2) an already rufus'ed USB?
    Fixed - when page-1 "Use an existing Live USB" is chosen, the Install
    working phase now short-circuits (mode "skip"): no ISO resolution, no
    download, no Rufus write. The drive letter is picked up and the lsl-usb
    files are dropped in place, so Mint (or Zorin) is never downloaded onto
    an already-rufus'ed stick.

[x] Offer to download Rufus (older version for Win7 etc.)
    Done - when Rufus is not installed, the installer now OFFERS to download
    it (console prompt) instead of silently fetching, and picks a version
    that runs on this OS: Windows 7 (and older) get the last Win7-compatible
    release (3.22); Windows 8+ get the latest. Unit tests added
    (rufus::tests::win7_and_older_get_win7_compatible_rufus,
    win8_and_newer_get_latest_rufus).

All builds green: cargo +rust9x build {debug,release} --target
i586-rust9x-windows-msvc; 27 unit tests pass under wine (6 hardware cache,
2 rufus version, 19 pre-existing).
